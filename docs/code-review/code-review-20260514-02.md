### 问题 1：增量扫描结果会清空未变化资产索引

**类型**： Bug修复

**模块**： `src/fwasset/core/services/scan_service.py`, `src/fwasset/core/file_scan.py`, `src/fwasset/core/asset_index.py`

**问题描述**
- `build_scan_result()` 将 `last_scan_at` 传给 `scan_firmware_assets()` 后，扫描结果只包含 mtime 较新的目录。
- 随后仍调用 `save_assets(assets, root)`；而 `save_assets()` 当前会先 `DELETE FROM assets`，再写入本次扫描结果。
- 因此第二次扫描若大部分目录未变化，会把未变化资产从 SQLite 索引中删除，UI 只剩本轮变更目录，甚至可能变为空。

**处理方案**
- 二选一：增量扫描阶段合并旧索引与本次变更结果后再保存；或在未实现合并前禁用 `last_scan_at` 下推，继续做全量扫描。
- 增加回归测试：先保存两个资产，再模拟其中一个目录未变化，扫描完成后索引仍保留两个资产。
- 如果要支持局部删除检测，需要明确按根目录/模型目录范围删除，而不是全表删除。

### 问题 2：扫描按钮显示取消时仍会打开目录选择器

**类型**： 用户体验

**模块**： `src/fwasset/ui/firmware_list_panel.py`

**问题描述**
- 扫描按钮创建时 `command=self._choose_root_and_scan`。
- 扫描开始后只把按钮文本改成“取消扫描”，没有切换 command。
- 用户点击“取消扫描”时会先弹出目录选择器；如果用户取消选择目录，`_scan()` 不会执行，`cancel_event` 不会被设置，后台扫描继续运行。

**处理方案**
- 将按钮 command 固定为一个调度函数：扫描中直接调用 `_scan()` 触发取消；未扫描时才调用 `_choose_root_and_scan()`。
- 或扫描开始时将按钮 command 改为 `_scan`，扫描结束后恢复为 `_choose_root_and_scan`。
- 增加 UI smoke 测试：扫描中点击按钮不调用 `filedialog.askdirectory`，而是设置现有 `_scan_cancel_event`。

### 问题 3：取消事件通过可变属性传入后台任务存在竞态

**类型**： Bug修复

**模块**： `src/fwasset/ui/firmware_list_panel.py`

**问题描述**
- `_work()` 内部读取 `self._scan_cancel_event` 并传给 `build_scan_result()`。
- 如果用户在后台线程实际执行 `_work()` 前点击取消，`_scan()` 会把事件 set 后立刻把 `self._scan_cancel_event` 置为 `None`。
- 后台线程随后可能拿到 `None`，导致取消信号丢失，扫描继续并可能写入索引。

**处理方案**
- 创建局部变量 `cancel_event = threading.Event()`，赋给 `self._scan_cancel_event` 后，闭包中始终传入该局部变量。
- 取消时只 set 事件，不要在后台任务完成前清空 `self._scan_cancel_event`；清理应放在 `_done()`。
- 增加测试覆盖：取消发生在任务启动后、工作函数读取事件前时，传入的仍是同一个 event。
