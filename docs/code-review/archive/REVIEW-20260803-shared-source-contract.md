## 审查目标

确保共享登记只允许同一规范模块的来源，且 Qt 入口不能通过任何切换或直接调用绕过该约束；同时使对话框聚焦于一次明确的来源选择。

## Issue 1：服务层未验证来源模块与目标模块一致  `complexity: medium`

当前 UI 的默认筛选虽按模块进行，但 service 接受任意 `module_key` 与来源资产组合，可能将来源模块写入另一目标模块键。

**要求：** 写入前对比两侧规范模块键；不一致返回 `module_mismatch`，来源模块缺失返回 `invalid_args`，两种情况均不得写入配置。

**处置：** ✅ 已完成。`set_shared_module()` 在任何路径与配置写入前完成模块键比较；服务回归覆盖不匹配来源与来源模块缺失，均断言不创建 `型号配置.toml`。

## Issue 2：Qt 对话框允许放开到全部资产  `complexity: medium`

候选构建后仍保留“只看同模块名 / 看全部”切换，使用户能够选择不相同模块；列表重复模块信息、长路径挤在单行、主要操作没有明确层级。

**要求：** 永久限定同模块的其它型号来源，删除切换；采用标题、简短说明、两行候选项、空状态和唯一主操作的结构。固定版本/自动更新与来源平台联动保持不变。

**处置：** ✅ 已完成。候选构建只传同模块的其它型号资产；对话框移除全部候选切换，使用 QFluentWidgets 主/次按钮、两行候选、完整路径 tooltip、空状态与未选择禁用确认。Qt 定向用例覆盖候选范围、无跨模块切换与显式选择后启用确认。
