1. **逐模型族处理**（按 L36 → L36S → L39 → L50 → L65 → L66 → L26 → L35 → L30 → G65 → 理疗椅 顺序）

   - 将对应的旧目录内容移动到新的子目录中

3. **保留旧根目录** `YJ-按摩椅家用，商用程序汇总` 作为备份，待验证无误后再决定删除
4. 已完成的 `L36程序/` 和 `L36S  程序/` 需要更新补充缺失内容

### 注意事项

- `旧/` 子目录保留在各自对应的板子类型目录内（带上下文），不创建全局 `旧/`
- 压缩包 `.zip/.rar` 保留在原位置（它们是备份文件）
- 接线图/PDF 等辅助文件保留在对应的 定制 或 通用 目录下
- 定制目录内的描述性子目录保留原始名称（如 `12模式/`、`带披肩加热/`、`不带中文UI/`）
- 空的 `（通用）` 目录保留，表示该组件与通用目录相同（不重复文件）

## Phase 2: 扫描器优化（重组后执行）

目录结构统一后，扫描器可以做以下增强：

### 2a. 关键词匹配简化

新结构中每个目录名规范统一，`firmware_catalog.toml` 的关键词可以更精确：

- `主板程序（通用）`、`主板/` → `mainboard`
- `蓝牙程序（通用）`、`蓝牙板/`、`蓝牙版/` → `music_bt`
- `语音程序（通用）`、`语音版/` → `voice`
- `快捷键（通用）`、`快捷键/` → `shortcut_key`
- `XD机芯板（通用）`、`机芯（通用）`、`机芯板/` → `movement_3d` / `movement_2d`
- `中英UI（通用）`、`手控/`、`手控器/` → `handcontrol_ui`
- `断码屏` → `segmented_screen`
- `音波板/` → `sonic_wave`
- `旋钮开关/` → `knob_switch`
- `接线图/` → `wiring_diagram`
- `三合一` → `three_in_one`
- `腿部程序/` → `leg_board`

之前 P0-P5 的问题（关键词缺失、型号正则不完整）在新结构下自然解决。

### 2b. 新增元数据提取

从路径中自动提取：

| 元数据 | 提取来源 | 示例值 |
|--------|---------|--------|
| `variant_type` | 路径第2级 | `通用` / `定制` / `测试` |
| `customer` | 定制目录名 | `以色列`、`凡强`、`林聘聘` |
| `country` | 目录名关键词 | `以色列`、`葡萄牙`、`越南` |
| `usage` | 目录名关键词 | `家用`（商用已独立） |
| `sub_model` | 路径中出现 | `L39MAX`、`L39S`、`L36S` |
| `mechanism_type` | 路径中出现 | `2D`、`3D`、`双机芯` |

### 2c. 数据库 Schema 扩展

在 `FirmwareAsset` 和 SQLite schema 中新增字段：
- `variant_type TEXT` — 通用/定制/测试
- `customer TEXT` — 客户名
- `country TEXT` — 目标国家
- `usage TEXT` — 家用/商用

这些字段支持按客户、国家、用途等维度搜索。
