## 二、核心数据层现状

### SQLite 数据库（Schema v3）

**`assets` 表关键列：**

| 列名 | 含义 |
|------|------|
| `path` | 固件目录的绝对路径（PK） |
| `model` | 型号，如 `L36` |
| `firmware_type` | 类型，如 `mainboard` / `handcontrol_ui` |
| `firmware_label` | 中文标签，如 `主板程序` / `手控UI` |
| `flash_mode` | 烧录方式：`auto_usb` / `tool_launch` / `manual_doc` / `disabled` |
| `directory_name` | 文件夹名，如 `量产_默认` / `以色列-Royal-Z9手控` |
| `category` | `common`（通用）/ `custom`（定制）/ `""`（旧目录） |
| `scheme_name` | 定制方案名，如 `以色列-Royal-Z9`；通用区为 `""` |
| `platform` | 平台名，如 `双机芯-上3D-下2D`；标准单机芯为 `""` |
| `version` | 从文件名提取的版本号 |
| `files` | 目录下的文件列表（JSON） |

**`query_assets()` 支持的过滤维度：**
- `keyword` → 全文搜索（model / version / label / directory_name / path / scheme_name / platform）
- `firmware_types` → 按类型过滤
- `category` → `common` / `custom`
- `scheme_name` → 按方案过滤
- `platform` → 按平台过滤
- `sort_key` + `ascending` → 排序

## 三、UI 层现状与问题

### 当前架构

```
UnifiedFlashPlatform (shell.py / CTk 窗口)
└── WorkbenchPanel (workbench_panel.py)
    ├── 左侧 Sidebar
    │   ├── CTkComboBox (型号切换)
    │   ├── CTkEntry (搜索框)
    │   ├── CTkScrollableFrame (树节点，用按钮模拟)
    │   └── 两个底部按钮（扫描 + 工具中心）
    └── 右侧 Main
        ├── CTkFrame (标题区 80px)
        ├── CTkScrollableFrame (卡片列表)  ← ⚠️ 性能瓶颈
        │   └── N × ModuleCard (每张卡片含按钮+标签)
        └── LogPanel
```

### ModuleCard 的问题（性能瓶颈根源）

每张卡片包含：
1. 标题文本（`CTkLabel`）
2. `📂` 按钮（`CTkButton`）
3. 来源标签（`CTkLabel`）
4. 烧录模式标签（`CTkLabel`）
5. **整个操作面板（`AutoUsbPanel` 或 `ToolLaunchPanel`）**

`AutoUsbPanel` 里包含：USB 选择器 + 4 个操作按钮
`ToolLaunchPanel` 里包含：工具信息 + 启动按钮 + 交接按钮

**结果**：打开「定制方案 → 马来西亚」时，同时渲染 8~12 张卡片，每张卡片里有 6~8 个 CTk 组件 → 总渲染约 60~100 个 CustomTkinter 组件。

CustomTkinter 的组件创建很慢（每个组件都有圆角画布绘制逻辑），所以卡顿明显。

### 当前的 4 个测试失败

`test_src_layout.py` 的 4 个测试写死了 `REPO_ROOT = Path(__file__).parent.parent`（在 `src/fwasset/tests/` 里往上两级是 `src/fwasset/`，而不是项目根目录），它们期望在 `src/fwasset/` 找到 `pyproject.toml` 和 `run.py`——这是测试文件本身写错了路径。

## 四、关键问题清单

### P0 必须修复（影响正常使用）
1. **UI 卡顿**：卡片式 + 每张卡实例化完整操作面板，组件数量爆炸
2. **扫描目录根目录逻辑**：`root_dir` 从 `settings.DEFAULT_ROOT` 读取，如果配置里是 `L36程序/` 的根目录，会正常工作；如果留空，弹窗选择才启动

### P1 体验改进（高优）
3. **按钮冗余**：卡片里有「复制目录路径」「复制主文件路径」等功能用户说不需要
4. **没有一眼看全**：用户无法在不下拉的情况下看到所有模块
5. **Win11/macOS 风格缺失**：使用 CustomTkinter 的默认控件，没有原生感

### P2 功能缺失（重要但非阻断）
6. **搜索维度不够**：当前关键字搜索是 OR 联合，无法按「型号 + 模块类型 + 国家」多级精准过滤
7. **无法增删改**：不能在 UI 内创建/重命名/删除文件夹
8. **定制模块缺失目录**：越南-娉娉-12模式 缺少主板，越南-娉娉-24模式 缺少语音——这是数据层面的现状，软件本身只能展示缺失信息

### 测试现状
- 152 个测试通过
- **4 个测试失败**（`test_src_layout.py` 4 条），但这是测试文件的路径写错了，不是业务 bug

## 五、技术可行性结论

| 需求 | 难度 | 说明 |
|------|------|------|
| 改为树形列表（TTK Treeview） | ⭐⭐ | 底层数据已就绪，只需重写 UI 渲染部分 |

| Win11/macOS 原生感 | ⭐⭐⭐ | 混合使用 ttk（原生 Treeview）+ CTk（按钮/输入框），颜色系统调整 |

## 六、下一步行动建议

**核心重构方向：用 `ttk.Treeview` 替换卡片流**

```
┌──────────────────────┬────────────────────────────────────────┐
│  左侧导航（不变）     │  右侧主区（重构）                       │
│                      │                                        │
│  [型号下拉]  [🔍搜索] │  ┌ 模块类型 │ 变体名 │ 版本 │ 来源 ┐   │
│                      │  │ 主板程序  │ 量产_默认 │ V40 │ 通用 │   │
│  ── 通用模块 ──       │  │ 主板程序  │ 防夹功能  │ V24 │ 通用 │   │
│   ├ 主板程序 (6)      │  │ 手控UI    │ 以色列    │ 120.3.1│定制│   │
│   ├ 手控UI (17)       │  │ 手控UI    │ 不带披肩  │ 38.3.1 │定制│   │
│   ...                 │  │ 蓝牙程序  │ 中文默认  │ V9  │ 回源 │   │
│  ── 定制方案 ──       │  └───────────────────────────────────┘   │
│   ├ 以色列-Royal-Z9   │                                        │
│   ├ 马来西亚-ROYAI    │  ── 选中行详情 & 操作 ──                │
│   ...                 │  双击行 → 打开文件夹                   │
└──────────────────────┴────────────────────────────────────────┘
```

**好处：**
- Treeview 是原生组件，100 行数据不会有卡顿
- 可以一眼看到所有变体（不需要卡片滚动）
- 原生 Win 风格感，支持列标题、排序
- 选中行后在底部显示操作区（而不是每行内嵌操作）
