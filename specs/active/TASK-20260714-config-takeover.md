## 为何此时新建 TASK（而不是继续 4.3）

- 迁移壳与功能对齐（4.1–4.2）已够支撑产线用 Qt 试验；**默认入口与打包**可延后，不阻塞业务能力。
- 现场目录（如 `D:\按摩器程序`）暴露的产品债是：**配置须软件接管**、**无 toml 不能禁用能力**、**跨型号共用是引用不是合并型号**——这些与「切默认 Qt」无关，且会动 core / 工作台语义，不宜塞进迁移收尾。
- 完整 CRUD 仍更后；先做配置闭环与共享引用骨架。

## 背景与目标

### 索引 / 工作区 vs 型号（术语）

当前索引语义（见 `asset_index` / 单工作区约定）：

| 概念 | 含义 |
| --- | --- |
| **固件工作区** | **一个**扫描根目录 = **一个** SQLite 索引生命周期；换根 = 换工作区，全表替换 |
| **多型号父根** | 工作区可以是父目录，例如 `D:\按摩器程序`，其下多个型号根 |
| **型号根** | 一级子目录（或单型号根自身），如 `L36程序`、`L36双机芯-上3D-下2D程序` |
| **回源作用域** | 方案缺模块时补通用的范围 = **本型号根内**（+ 显式共享引用，见 Phase B） |

**禁止误解**：切换型号 **≠** 切换数据库 / 清空索引。型号切换只换 UI 过滤与配置读写路径，索引仍服务整个固件工作区。

### 产品约束（不可变）

1. **独立型号 = 独立型号根 + 独立回源作用域**；多个型号根可以共同位于**同一固件工作区**中。一级型号目录不合并。  
   - 例：`按摩器程序/L36程序` 与 `按摩器程序/L36双机芯-…` 同工作区、分型号根、回源互不串。
2. **方案缺模块的「通用默认」回源仅限本型号根内**（本型号 `通用/` + 本型号模块默认）。跨型号只能走 **Phase B 显式共享引用**，禁止静默搜索同名模块「偷」程序。
3. **`平台配置.toml` / 方案 toml = 应用内部状态**：用户零手写；UI 不出现「请编辑 toml」类要求。
4. **现场共享关系**（占位目录已体现）：L36 双机芯多数模块规划与 **L50S / L50S-L66S 双机芯共用**；与 L36 实装相同的主要是**快捷键**等少数项。命名与 `.ref` 仍是占位，未真正整理完。
5. **不在本 TASK 做完整程序 CRUD**（导入/替换/删除/移动、**复制为本型号私有**）；可做配置/引用元数据的最小写盘。

### 双机芯目录判定（写进契约）

`L36双机芯-上3D-下2D程序`：

| 是 | 不是 |
| --- | --- |
| **独立展示的整机程序包**（型号列表中独立出现，方便烧录员搜整机） | 自动继承 L36 的通用默认 |
| L36 产品家族下的**配置变体 / 关联包**（人话叙事） | 与 L36 合并为同一型号根 |
| 通过 **共享引用** 明确使用 L50S-L66S 共用模块（Phase B） | 静默跨型号回源到 L36 或 L50 |

### 目标

让烧录员只通过软件完成：

- 无配置型号也能浏览、设默认、（有方案时）回源；
- 内部自动创建/更新配置文件（含「无 toml 但已有方案」的初始化规则）；
- 跨型号共用以**稳定标识的显式共享引用**表达（查看、跳转来源；来源缺失明示）；
- Phase C：`follow_default` / `pinned`（仍是引用）；**不**做文件拷贝脱钩。

### 非目标（另立 TASK）

- `app.py` 默认 Qt、PyInstaller 交付（迁回 `TASK-20260708` Phase 4.3+）。
- 完整固件 CRUD、扫描退化为对账冷路径。
- **`copied`（复制为本型号私有模块）** → 固件 CRUD TASK。
- 物理删除 CTk（`ui/`）。
- 合并双机芯进 `L36程序` 目录。

## 分阶段计划

### Phase A — 配置闭环（优先，约 0.5–1 日）

对应 `task-exchange` 第 1–2 步（**同一里程碑**）。

| # | 项 | 说明 |
| --- | --- | --- |
| A1 | 无配置可设默认 | 去掉「未找到平台配置」禁用；UI 在无 toml 时仍可点「设为「型号」模块默认」 |
| A2 | 首次初始化规则（**必遵守**） | 见下方 **A2 细则**；禁止无脑只建 `name = "默认"` 而忽略方案已有的 `platform` |
| A3 | 型号+模块默认 | 业务主语始终「型号 + 模块」；用户设置的默认**同步写入该型号根下全部** `[[platform]]` 块 |
| A4 | 无键推断 | 某模块在本型号通用区**唯一变体** → 隐式默认（对齐 `defaults[模块]=""`）；多变体且无键 → 不猜 |
| A5 | 方案回源 | 定制优先 → 按方案 `platform` 名匹配配置块 → 本型号默认/推断 → 补「通用」行；块名与方案对不上则回源仍失败（靠 A2 避免） |
| A6 | 双轨 UI | CTk + Qt 菜单/确认文案一致；无配置时与有配置相同（可设 / 已是默认） |
| A7 | 测试 | 无文件首次写入；**无 toml 但方案已声明 platform**；推断；同工作区多型号根配置路径隔离（**不**换库） |

#### A2 首次初始化规则（无 `平台配置.toml` 或等价空配置时）

1. 收集**本型号根**内所有方案配置（`定制/*/方案配置.toml` 等）中的 `platform` 名称（去重、去空）。  
2. **若存在至少一个非空 platform 名**：为**每个**名称生成一个 `[[platform]]` 配置块（`name` = 该字符串）。  
3. 用户设置的「型号 + 模块默认版本」**同步写入全部**配置块（与现有 `set_module_default_for_model` 方向一致）。  
4. **仅当**没有任何方案、或所有方案都没有 platform 名称时，才生成单一块 `name = "默认"`（内部名，不作为用户主语展示）。  
5. 已有 toml 时：不删除用户/历史块；设默认仍写全部块；缺的模块键按需追加。

**错误示范**：方案写 `platform = "标准单机芯3D"`，初始化却只建 `默认` → 方案按名找不到块 → 首次设默认后回源仍不生效。A2 必须避免此情况。

**完成定义 A**：

- 任意型号根（含仅有 `通用/`、无 toml 的双机芯占位）右键可设默认并落盘；  
- **无 toml 但已有定制方案**时，首次设默认后方案声明的 platform 块已存在，回源可用；  
- 不依赖人手写 toml。

### Phase B — 共享模块引用（骨架）

对应 `task-exchange` 第 3 步。

| # | 项 | 说明 |
| --- | --- | --- |
| B1 | 稳定标识数据模型 | **不能只有自由路径**；见下方 schema（路径基准与 `source_model_id` **已写死**）。存储位置（型号内 toml 段 / 独立文件）实施时定，**用户仍不手写** |
| B2 | 发现/登记 | 软件侧登记共享；`.ref` **仅作迁移提示/一次性导入备忘**，**不是**长期业务解析协议 |
| B3 | UI | 角标/归属：**共享自 …**（禁「回源」）；右键打开来源；**来源缺失**明示，见 B6 |
| B4 | 与方案回源边界 | 共享引用 **≠** 方案缺模块时的自动回源；方案回源仍只读**本型号**通用 + 默认 |
| B5 | 与 L50 叙事 | 双机芯默认指向 L50S-L66S 共用组；**不**全盘自动猜共用 |
| B6 | 解析失败 | 源不存在 → UI **「共享来源缺失」**；**禁止**静默跨型号搜相似/同名模块补入 |

#### B1 引用 schema（最少字段；**实现前写死，禁止实现时临时改基准**）

> 非 Phase A 阻塞项；**B1 编码前必须遵守本节**，不得在实现时再选「相对工作区还是源型号根」。

**路径基准（已定）：**

- `source_relative_path` **永远相对固件工作区根**（扫描根，如 `D:\按摩器程序`）。  
- **禁止**相对当前型号根、源型号根、或「二选一临时决定」。  
- 错误示范：双机芯型号内解析时把 `通用/L50S-…/手控` 接到 `L36双机芯-…/` 下。  
- 正确：路径自带源型号目录段，从工作区根拼绝对路径。

**型号身份（已定）：**

- `source_model_id` 由**型号配置中的持久 id** 生成/保存（小写稳定串，如 `l50`）。  
- **目录名仅用于首次导入与 UI 显示**，不能作为唯一稳定身份。  
- 目录改名、展示名调整后，仍用 `source_model_id` 校验引用目标属于正确源型号（再结合路径存在性）。

```toml
# 示意：键名可微调，语义与路径基准不可弱化
[shared_modules."手控UI"]
source_model_id = "l50"
source_group = "l50s-l66s-dual"
source_module = "手控UI"
source_relative_path = "L50程序/通用/L50S-L66S双机芯共用/手控"
mode = "follow_default"   # 或 Phase C 的 "pinned"；不做 "copied"
```

| 字段 | 作用 |
| --- | --- |
| `source_model_id` | 源型号**持久 id**（配置内生成）；非目录名主键 |
| `source_group` | 源侧分组/共用区 id（如 `l50s-l66s-dual`） |
| `source_module` | 源模块逻辑名 |
| `source_relative_path` | **相对固件工作区根** 的路径（含源型号目录前缀）；用于解析与跳转 |
| `mode` | `follow_default` / `pinned`（Phase C）；**无** `copied` |

**解析约束：**

- 绝对路径 = `工作区根 / source_relative_path`；结果必须落在当前固件工作区内（防 `..` 逃逸）。  
- 解析时校验：路径所属型号与 `source_model_id` 一致（按型号配置的持久 id 映射，而非裸目录字符串匹配）。  
- 来源缺失 → 「共享来源缺失」，不静默回退、不跨型号模糊匹配。  
- **不允许引用链递归解析**，更不能形成循环（A→B→A）。  
- `.ref` 文件：可选迁移导入生成上述结构后，业务只认正规引用。  

**完成定义 B**：至少一个共享引用可登记、列表可见、可按稳定标识解析并跳转；来源删除/改名后显示缺失；双机芯可演示「手控/机芯 → L50 共用」而不合并型号、不继承 L36 默认。

### Phase C — follow_default / pinned（可选增强）

对应 `task-exchange` 第 4 步。**Phase B 可用后再做**。

| mode | 含义 | 本 TASK |
| --- | --- | --- |
| **`follow_default`** | 仍是引用；跟随源侧当前默认/当前文件 | ✅ 做 |
| **`pinned`** | 仍是引用；**钉住**某一来源变体（或解析快照标识），源侧换默认不牵动本型号 | ✅ 做 |
| **`copied`** | 复制到本型号目录后与来源**完全脱钩** | ❌ **不做** → 固件 CRUD TASK |

说明：旧文「固定 = 拷贝或钉版本」已废弃。**pinned ≠ 拷贝**；拷贝会引入文件复制、索引更新、冲突恢复等完整 CRUD 问题，本 TASK 不提前做。

防误目标：共享源升级时，`pinned` 型号不被误伤；`follow_default` 型号有意跟随。

## 验收场景（人验）

1. **L36 有 toml**：设默认、★默认、方案缺模块补通用——行为不回退。  
2. **L36 双机芯无 toml**：能扫到已有 bin/hex；右键设默认 → 型号根下出现内部配置；无「未找到平台配置」禁用。  
3. **不跨型号静默补（回源）**：双机芯方案（若有）缺模块时只从**本型号**通用/默认补，不会自动出现 L36 主板。  
4. **（Phase B）** 共享引用可见；可按稳定标识打开来源（L50 共用区等）。  
5. **无 TOML 但已有定制方案**：首次设置默认后，方案声明的 `platform` 配置块被自动初始化，方案回源**立即生效**（不为孤岛块 `默认` 而方案仍写 `标准单机芯3D`）。  
6. **共享引用来源缺失**（Phase B）：UI 显示 **「共享来源缺失」**；不跨型号自动搜索相似模块；不把 L50/L36 同名程序静默补入。
