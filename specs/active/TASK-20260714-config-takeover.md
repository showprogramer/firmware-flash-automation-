## 背景与目标

### 索引 / 工作区 vs 型号（术语）

当前索引语义（见 `asset_index` / 单工作区约定）：

| 概念 | 含义 |
| --- | --- |
| **固件工作区** | **一个**扫描根目录 = **一个** SQLite 索引生命周期；换根 = 换工作区，全表替换 |
| **多型号父根** | 工作区可以是父目录，例如 `D:\按摩器程序`，其下多个型号根 |
| **型号根** | 一级子目录（或单型号根自身），如 `L36程序`、`L36双机芯-上3D-下2D程序` |
| **方案回源作用域** | 方案缺模块时补齐范围 = **仅本型号根内**的通用资产 + **本型号**默认配置（`平台配置.toml`）。**不含**显式共享引用 |
| **显式共享引用** | Phase B：跨型号指针（`型号配置.toml` 的 `shared_modules`）。**独立**浏览 / 跳转 / 烧录路径，**不属于**方案回源作用域 |

**禁止误解**：

- 切换型号 **≠** 切换数据库 / 清空索引。型号切换只换 UI 过滤与配置读写路径，索引仍服务整个固件工作区。  
- **禁止**把「方案回源」理解成「本型号通用 + 共享引用」——旧表述已废止；共享与回源**永不交叉**（B4）。

### 产品约束（不可变）

1. **独立型号 = 独立型号根 + 独立回源作用域**；多个型号根可以共同位于**同一固件工作区**中。一级型号目录不合并。  
   - 例：`按摩器程序/L36程序` 与 `按摩器程序/L36双机芯-…` 同工作区、分型号根、回源互不串。
2. **方案回源仅限本型号根内**（本型号 `通用/` + 本型号模块默认）。  
   - **不得**在方案树/方案回源路径中顺带展开 `shared_modules`（例如方案缺蓝牙时**不**自动显示已登记的 L50 共享蓝牙）。  
   - 跨型号真身只走 **Phase B 显式共享**（列表共享态 / 角标 / 跳转 / 烧录），禁止静默搜索同名模块「偷」程序。
3. **双文件内部状态**（用户零手写）：  
   - `平台配置.toml` → 仅 `[[platform]]` + 模块默认；  
   - `型号配置.toml` → `model_id` + `shared_modules`；  
   - 方案 toml 等仍由软件托管。
4. **现场共享关系**（占位目录已体现）：L36 双机芯多数模块规划与 **L50S / L50S-L66S 双机芯共用**；与 L36 实装相同的主要是**快捷键**等少数项。命名与 `.ref` 仍是占位，未真正整理完；**是否共用由烧录员登记**，软件不自动认亲。
5. **不在本 TASK 做完整程序 CRUD**（导入/替换/删除/移动、**复制为本型号私有**）；可做配置/引用元数据的最小写盘。设为共享**不删除**目标型号目录内已有文件（见「本地副本与共享覆盖」）。
### 双机芯目录判定（写进契约）

`L36双机芯-上3D-下2D程序`：

| 是 | 不是 |
| --- | --- |
| **独立展示的整机程序包**（型号列表中独立出现，方便烧录员搜整机） | 自动继承 L36 的通用默认 |
| L36 产品家族下的**配置变体 / 关联包**（人话叙事） | 与 L36 合并为同一型号根 |
| 通过 **共享引用** 明确使用 L50S-L66S 共用模块（Phase B） | 静默跨型号回源到 L36 或 L50 |

### 目标

让烧录员只通过软件完成：

- 无配置型号也能浏览、设默认、（有方案时）回源；
- 内部自动创建/更新配置文件（含「无 toml 但已有方案」的初始化规则）；
- 跨型号共用以**稳定标识的显式共享引用**表达（查看、跳转来源；来源缺失明示）；
- Phase C：`follow_default` / `pinned`（仍是引用）；**不**做文件拷贝脱钩。

### 非目标（另立 TASK）

- 完整固件 CRUD、扫描退化为对账冷路径。
- **`copied`（复制为本型号私有模块）** → 固件 CRUD TASK。
- 物理删除 CTk（`ui/`）。
- 合并双机芯进 `L36程序` 目录。

## 分阶段计划

### Phase A — 配置闭环（优先，约 0.5–1 日）

对应 `task-exchange` 第 1–2 步（**同一里程碑**）。

| # | 项 | 说明 |
| --- | --- | --- |
| A1 | 无配置可设默认 | 去掉「未找到平台配置」禁用；UI 在无 toml 时仍可点「设为「型号」模块默认」 |
| A2 | 首次初始化规则（**必遵守**） | 见下方 **A2 细则**；禁止无脑只建 `name = "默认"` 而忽略方案已有的 `platform` |
| A3 | 型号+模块默认 | 业务主语始终「型号 + 模块」；用户设置的默认**同步写入该型号根下全部** `[[platform]]` 块 |
| A4 | 无键推断 | 某模块在本型号通用区**唯一变体** → 隐式默认（对齐 `defaults[模块]=""`）；多变体且无键 → 不猜 |
| A5 | 方案回源 | 定制优先 → 按方案 `platform` 名匹配配置块 → 本型号默认/推断 → 补「通用」行；块名与方案对不上则回源仍失败（靠 A2 避免）。**不含** `shared_modules`（见 B4） |

| A7 | 测试 | 无文件首次写入；**无 toml 但方案已声明 platform**；推断；同工作区多型号根配置路径隔离（**不**换库） |

#### A2 首次初始化规则（无 `平台配置.toml` 或等价空配置时）

1. 收集**本型号根**内所有方案配置（`定制/*/方案配置.toml` 等）中的 `platform` 名称（去重、去空）。  
2. **若存在至少一个非空 platform 名**：为**每个**名称生成一个 `[[platform]]` 配置块（`name` = 该字符串）。  
3. 用户设置的「型号 + 模块默认版本」**同步写入全部**配置块（与现有 `set_module_default_for_model` 方向一致）。  
4. **仅当**没有任何方案、或所有方案都没有 platform 名称时，才生成单一块 `name = "默认"`（内部名，不作为用户主语展示）。  
5. 已有 toml 时：不删除用户/历史块；设默认仍写全部块；缺的模块键按需追加。

**错误示范**：方案写 `platform = "标准单机芯3D"`，初始化却只建 `默认` → 方案按名找不到块 → 首次设默认后回源仍不生效。A2 必须避免此情况。

**完成定义 A**：

- 任意型号根（含仅有 `通用/`、无 toml 的双机芯占位）右键可设默认并落盘；  
- **无 toml 但已有定制方案**时，首次设默认后方案声明的 platform 块已存在，回源可用；  
- 不依赖人手写 toml。

### Phase B — 共享模块引用（骨架）

对应 `task-exchange` 第 3 步。

#### 已定路线（讨论闭环 2026-07-16 起；落盘/mode/登记入口 2026-07 审查补强，实现前不再翻）

1. **软件登记，不碰文件**：共享 = **引用（指针）**，绝不复制文件。软件**写引用元数据**到 **`型号配置.toml`**（用户零手写）。不碰 bin/hex 本身（复制/移动/删除留给 firmware-crud TASK）。
2. **两类源统一一套解析器**：「源已在工作区」与「源未导入」共用同一解析路径；后者走**缺失分支**（B6）。**不**写第二套解析代码。
3. **登记入口分两种**（见 B2）：  
   - **手动「设为共享」**：只能选**当前工作区内已发现的真实来源资产**；  
   - **源尚未导入**的预期引用：只能由 **`.ref` 一次性迁移导入**生成（预览 + 用户确认；不静默覆盖；幂等）。
4. **`.ref` / `-同L50S` 命名 = 一次性迁移线索**：仅迁移导入时读；之后业务**只认** `型号配置.toml` 里的正规引用。
5. **共享 vs 方案回源，两条永不交叉的路径**：见 B4。
6. **落盘与 `平台配置.toml` 严格分离**（见「落盘文件」）：**禁止**把 `model_id` / `shared_modules` 写入 `平台配置.toml`（`save_platform_config` 会整文件重写，会删掉共享段）。
7. **Phase B 不存、不解析 `mode`**：引用指向**确定物理路径**；多变体时 UI 列出源侧变体由用户选烧；`follow_default` / `pinned` **仅 Phase C**。

| # | 项 | 说明 |
| --- | --- | --- |
| **B0** | **型号持久 id（前置）** | 见 **B0 专节**。id **只**写在 `型号根/型号配置.toml`。 |
| B1 | 稳定标识数据模型 | 见下方 schema；**落盘文件已写死**为 `型号配置.toml`；**无 `mode` 字段（B 期）** |
| B2 | 发现/登记 | **手动**：仅工作区内真实资产；**迁移**：`.ref` 预览确认；不静默覆盖；幂等 |
| B3 | UI | 角标 **共享自 …**；打开来源；命中可烧（按路径解析出的资产/变体）；缺失灰掉 |
| B4 | 与方案回源边界 | 共享 ≠ 方案回源；互不调用；见 B4 专节 |
| B4b | 本地副本与共享覆盖 | 模块级二选一有效态；见专节 |

#### 落盘文件（B0/B1 **已写死**，禁止实施时另选）

| 文件 | 路径 | 承载 | **禁止** |
| --- | --- | --- | --- |
| **`型号配置.toml`** | **型号根/**`型号配置.toml` | `model_id` + `[shared_modules.*]` | 模块默认、`[[platform]]` |
| **`平台配置.toml`** | 型号根/`平台配置.toml` | **仅** `[[platform]]` + `defaults`（模块默认变体） | `model_id`、`shared_modules`、任何共享字段 |

- 落盘目录 = **型号根**（与 `_platform_config_root` 同级纪律），**禁止**写进 `通用/`。  
- 读写 `型号配置.toml` 必须用**独立** load/save（读写-合并-写回），**不得**调用 `save_platform_config` 去碰该文件。  
- 理由：`save_platform_config()` 整体重写 `平台配置.toml` 且只输出 platform 块；若共享写进同文件，「设为默认」会**删光** `model_id` / `shared_modules`。

**`型号配置.toml` 最小格式（B0+B1 合一文件）：**

```toml
# 本文件由 fwasset 管理（型号 id + 共享引用）。用户无需手写。
# display_name 不落盘（永远由目录名现推）。

model_id = "l36双机芯-上3d-下2d"

[shared_modules."快捷键程序"]
source_model_id = "l36"
source_group = "l36-single"
source_module = "快捷键程序"
# 相对固件工作区根；可指到变体目录（固定某一变体）或模块目录（多变体由用户选烧）
source_relative_path = "L36程序/通用/快捷键/贝乐"
# Phase B：禁止写入 mode；Phase C 再增加 follow_default / pinned
```

- **B0 仅首次**可只写 `model_id` 一行；有共享后再写 `shared_modules` 段。  
- 保存共享引用时**保留**已有 `model_id`；保存 id 时**保留**已有 `shared_modules`。
#### B0 型号持久 id（前置；实现前写死）

> 当前工作台只有目录现推展示名（`_strip_model_suffix` → `_multi_model_dirs`），**无稳定身份**。  
> 共享引用的 `source_model_id`、改名校验、源未导入时的身份保留都依赖 B0。  
> **范围收窄**：只做「落盘 + 映射 + 供 B1 用的 API」；**不**把 UI 选型键整库改成 id。  
> **代码前置**：`TASK-20260716` 已合入；写 `型号配置.toml` **必须**复用其 `atomic_write_text`（或同等原子写），禁止 `Path.write_text` 直接覆盖。

##### 三名分离（不可揉成一个字符串）

| 概念 | 是否落盘（B0） | 例 | 用途 |
| --- | --- | --- | --- |
| **`model_id`** | **是**（唯一必写字段） | `l50`、`l36`、`l36双机芯-上3d-下2d` | 稳定主键；配置与共享引用；目录改名不变 |
| **`display_name`** | **否** | `L50`、`L36`、`L36双机芯-上3D-下2D` | 下拉 / 侧栏 / 日志；**永远** `_strip_model_suffix(dir_name)` 现推 |
| **`dir_name`** | 否（即目录本身） | `L50程序`、`L36程序` | 工作区下一级目录名；可变 |

- **B0 定论：`display_name` 不存盘。** 配置里只落 `model_id` 一个字段。目录改名后展示名随 `dir_name` 变——符合直觉，也少一个要维护的状态。  
- 将来若要把 `L36双机芯-上3D-下2D` 显示成「L36 双机芯」等**脱离目录名**的展示，在 **firmware-crud / 后续 TASK** 再加可选 `display_name` 落盘；**B0 示意 toml 不写该字段**（可在注释中标「预留，B0 不写」）。  
- 资产字段 `model`（文件名解析）**绝不能**当 `model_id`。  
- Phase B：UI 继续以现推的 `display_name` 选型号；内部维护 `model_id ↔ dir_name`（及现推 display）；**只有共享引用写 `source_model_id`**。

##### 存哪

- **唯一落盘文件**：型号根下的 **`型号配置.toml`**（见上文「落盘文件」专节）。  
- **B0 写入内容**：仅确保存在 `model_id = "..."`；**不**写 `display_name`；**不**触碰 `平台配置.toml`。  
- **解析侧**：扫描/bind 时建**内存表**（工作区内）：  
  `model_id ↔ dir_name`，`display_name = _strip_model_suffix(dir_name)`（现推，不读盘）  
  以及 `model_root_for_id(id) → Path | None`。  
  **不必**先做工作区总注册表文件；找不到 id → B6 缺失即可。  
- **改名**：`型号配置.toml` 随目录移动；`model_id` 在文件内不变；展示名随新目录名现推；重扫后靠读配置重建 id 映射。
##### 首次生成 slug 与实现顺序（已有 id 则永不重算）

**实现顺序（必遵守，避免误分 `-2`）：**

1. **先读全量**：遍历工作区内全部已发现型号根，读出已有合法 `model_id`，记入占用集合。  
2. **再生成**：仅对**尚无** `model_id` 的型号根做 slug；与占用集合碰撞则 `-2`、`-3`…，写入后把新 id 加入占用集合。  
3. **禁止**在未读完全量已有 id 之前给任一新型号分配 slug（否则可能把本可稳定为 `l36` 的老型号误分成 `l36-2`，或与已写死 id 的根冲突）。

**slug 规则：**

1. 取 `dir_name`（如 `L50程序`、`L36双机芯-上3D-下2D程序`）。  
2. 去掉尾缀 `程序` / `目录`。  
3. **ASCII 字母数字段转小写**；中文保留；空白压成 `-`；去掉路径危险字符。  
   - 例：`L50程序` → `l50`；`L36程序` → `l36`；`L36双机芯-上3D-下2D程序` → `l36双机芯-上3d-下2d`。  
4. **同工作区碰撞**（相对步骤 1 的占用集合）：后缀 `-2`、`-3`…，并打日志。  
5. **关键**：型号根已存在合法 `model_id` → **只读、永不按目录重算覆盖**（改名安全的核心；`-2` 一旦写入也永久稳定，不因碰撞方移走而「升回」`l36`）。  
6. 写入失败 → 服务结果失败，不静默用展示名冒充 id。

##### 与现码映射（加层，不推翻）

- 保留 `_multi_model_dirs: display_name → dir_name` 等现有键，**另加** id 映射层。  
- 供 B1 的最小 API（名称可调整）：  
  - `ensure_model_ids(workspace_roots) → …`（内部：先读全量已有 id，再为无 id 者生成）  
  - `resolve_model_id(display_name | dir_name) → model_id | None`

- **解析**：引用里可保留 `source_model_id` + 相对路径，即使源不在工作区 → **来源缺失**（与文件被删同一分支）。  
- **登记**：B0 不负责创建「源未导入」的引用；见 B2（仅迁移可写这类引用）。

5. **B0 完成后才允许开 B1**。

#### B1 引用 schema（最少字段；**实现前写死**）

> **B0 完成后**才编码。落盘文件、路径基准、**无 mode** 均已定。

**路径基准（已定）：**

- `source_relative_path` **永远相对固件工作区根**。  
- **禁止**相对当前型号根 / 源型号根 / 实施时二选一。  
- 正确：路径含源型号目录段，如 `L36程序/通用/快捷键/贝乐` 或 `L50程序/通用/L50S-L66S双机芯共用/手控`。

**型号身份（已定，依赖 B0）：**

- `source_model_id` = B0 的 `model_id`。  
- 解析校验：路径第一段所属型号根的 `model_id == source_model_id`。

**Phase B 字段（无 `mode`）：**

| 字段 | 作用 |
| --- | --- |
| `source_model_id` | 源型号持久 id |
| `source_group` | 源侧分组/共用区 id（如 `l50s-l66s-dual`、`l36-single`） |
| `source_module` | 源模块逻辑名 |
| `source_relative_path` | **相对工作区根** 的确定物理路径（模块目录 **或** 变体目录） |

- **Phase B 禁止**在 toml / 解析器中出现 `mode`、`follow_default`、`pinned`。  
- **路径粒度**：  
  - 固定某一变体（如快捷键贝乐）→ `source_relative_path` **直接指到该变体目录**；  
  - 指到模块目录且其下多变体 → UI **列出源侧全部变体**，用户选中后再烧（B 期不做自动跟默认）。  
- 完整文件示例见上文「落盘文件」中的 `型号配置.toml`。

**解析约束（一套解析器）：**

- 绝对路径 = `工作区根 / source_relative_path`；必须在工作区内（防 `..`）。  
- **命中**：源已导入 + 路径存在 + id 相符 → 「共享自 …」、可跳转；可烧 = 解析到具体资产/用户选中的变体。  
- **缺失**：源未导入 / 路径无 / id 不符 → 「共享来源缺失」，灰掉不可烧；不静默跨型号搜同名。  
- **禁止**引用链递归与循环。  
- 业务只认 `型号配置.toml` 中的正规引用（迁移生成后亦然）。

#### B2 登记入口（已写死）

| 入口 | 允许 | 禁止 |
| --- | --- | --- |
| **手动「设为共享」** | 仅选择**当前工作区内已扫描到的真实来源资产**（可解析出 `source_model_id` + 工作区相对路径） | 手填未导入型号、空路径、猜同名 |
| **`.ref` / 命名迁移** | 一次性导入：读线索 → **预览** → **用户确认** 后写入 `型号配置.toml` | 静默覆盖已有同模块引用；无确认直接写 |
| **幂等** | 重复执行迁移：已存在且相同则跳过；不产生重复键 | 每次导入追加重复 `shared_modules` 项 |

- 同一目标模块已有引用：**不静默覆盖**；UI 提示冲突，由用户选择覆盖或取消。  
- 迁移可生成「源尚未在工作区」的引用 → 解析即缺失，直至用户扫入源型号；与手动入口分离，避免右键无资产可选却要填安全路径的死胡同。

#### B3 UI（Phase B）

- 角标/归属：**共享自 {源展示名或 id}**（禁「回源」）。  
- 右键：打开来源目录；命中时可烧（单路径直接烧；多变体先选变体）。  
- 缺失：**共享来源缺失**，操作灰掉（**不**提示改用保留本地副本）。  
- 普通模块列表 / 烧录候选：该模块若处于 shared 有效态，**只显示共享来源**，不并列本地副本。

#### B4 共享 vs 方案回源（永不交叉；已写死）

| 路径 | 做什么 | 不做什么 |
| --- | --- | --- |
| **方案回源** | 方案缺模块 → 本型号 `通用/` + 本型号默认配置补「通用」行 | **不**读 `shared_modules`；**不**把共享源画进方案树当回源 |
| **显式共享** | 模块列表共享态、角标、打开源、按引用烧 | **不**参与 `get_scheme_modules` 回源补洞 |

- 定制方案缺「蓝牙程序」、但本型号已登记 L50 共享蓝牙 → **方案页不出现该共享蓝牙**；蓝牙若方案也无定制专属 → 方案上该模块**缺失**（除非本型号通用回源能补）。  
- 共享蓝牙只在共享/模块浏览路径可见与可烧。  
- 与产品约束 2、术语表「方案回源作用域」一致；旧句「回源 = 本型号 + 显式共享」**作废**。

#### B4b 本地副本与共享覆盖（已写死）

场景：目标型号目录里已有同模块文件（如双机芯本地快捷键），烧录员后来登记共享自 L36 某变体。

| 规则 | 契约 |
| --- | --- |
| **键** | `shared_modules` 的键 = 目标型号的**规范模块键**（`canonical_module_dir`，如 `3D机芯板程序` / `快捷键` 与 catalog 一致）；`source_module` 同样用规范名。**禁止** `机芯版`/`机芯板` 各成一条引用。 |
| **有效态** | 同一目标模块在 Phase B **不能**同时处于 local 与 shared 两种**有效**状态；有 `shared_modules` 键 ⇒ 该模块 **shared 有效**。 |
| **设为共享后** | 目标型号目录中原有同模块文件**不移动、不删除**，称为**保留本地副本**；扫描索引仍可发现它们（对账/迁移），但**普通模块列表与烧录候选只显示共享来源**，不同时显示两份。 |
| **共享来源缺失** | 显示「共享来源缺失」，灰掉不可烧；**禁止**静默改用保留本地副本。 |
| **取消共享** | 只删除该 `shared_modules` 条目；**不删除任何文件**；保留本地副本立刻恢复为该模块的有效本地资产。 |
| **与方案页** | 维持 B4：方案页**既不**顺共享引用补模块，**也不得**绕过共享状态把保留本地副本当作方案回源。该模块在方案上若无定制专属且本型号通用回源也补不上 → **明确缺失**。 |

#### 完成定义 B

- B0 完成；`TASK-20260716` 已合入（原子写可被 B0/B1 复用）。  
- 至少一条共享引用可经手动或迁移写入 `型号配置.toml`；列表可见；解析命中/缺失正确。  
- 设默认不破坏 `型号配置.toml`；无 `mode` 字段。  
- 方案回源与共享路径隔离（B4）；本地副本规则（B4b）有测试。  
- 双机芯可演示共享自 L50/L36 而不合并型号。
