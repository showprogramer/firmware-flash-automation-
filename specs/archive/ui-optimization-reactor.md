# UI 重设计方案

> **目标**：解决三个核心问题
> 1. 操作卡顿
> 2. 资源条目区域太小，须大量下拉
> 3. 筛选栏过长 + 操作区浪费空间
>
> **根本原则**：这是一个"找程序 → 打开工具"的工具，不是资产管理后台。UI 要服从这个工作流。

---

## 一、卡顿的根本原因与修复

### 诊断

当前卡顿来自两处：

| 来源 | 为什么卡 |
|------|---------|
| `CTkScrollableFrame` + 大量 `CTkFrame/CTkLabel` 卡片 | 每张卡片是 4~6 个 CTk widget，100 条资产 = 400~600 个组件同时存活在内存中，布局计算量巨大 |
| `_filter_assets()` 每次调用都销毁并重建所有卡片 | `widget.destroy()` + `CTkFrame()` 在主线程同步执行，卡顿直接可见 |

### 修复方案：用 `ttk.Treeview` 替换卡片列表

`ttk.Treeview` 是 tkinter 原生组件，**虚拟渲染**——只绘制可见行，1000 行和 50 行性能无差异。

```python
# 替换前：每条资产 = 4~6 个 CTk widget
card = ctk.CTkFrame(...)          # widget 1
title_label = ctk.CTkLabel(...)   # widget 2
meta_label = ctk.CTkLabel(...)    # widget 3
type_label = ctk.CTkLabel(...)    # widget 4

# 替换后：整个列表 = 1 个 Treeview，所有行是数据行
tree.insert("", "end", iid=asset_path, values=(model, version, fw_label, flash_mode))
```

**性能对比**（300 条资产）：

| 方案 | 初始渲染 | 筛选刷新 | 内存占用 |
|------|---------|---------|---------|
| CTk 卡片（当前） | ~800ms | ~600ms | 高 |
| ttk.Treeview（建议） | <50ms | <20ms | 低 |

树形结构（系列→型号→固件类型）天然适合 Treeview 的 `parent` 参数，不需要额外实现折叠逻辑。

## 二、布局重设计

### 当前布局的问题

```
┌──────────────── 70% ────────────────┬──── 30% ────┐
│ 品牌标题 + 工具中心按钮              │ 操作区       │
│ 搜索框 + 排序                        │ （过大）     │
│ 固件类型筛选卡片（纵向长列表）        │             │
│   □ 手控UI   □ 主板程序  ...         │ 资源详情     │
│   （多达 19 个复选框）               │ （重复信息） │
│ 资源条目（只剩一点点高度）            │             │
│   树节点折叠/展开                    │             │
│   条目卡片...                        │             │
└─────────────────────────────────────┴─────────────┘
```

**核心问题**：筛选卡片吃掉了侧边栏约 40% 高度，留给资源条目的空间太少。

### 新布局方案

```
│ ⚡ 固件资产管理系统            [🔧 工具中心]  [扫描目录] │  ← 顶部工具栏（单行）
├──────────────────────────────────────────────┬─────────┤

├──────────────────────────────────────────────┤  操作区  │
│ 系列  │ 型号目录名          │ 固件类型  │ 版本 │  30%宽  │  ← Treeview 表头
├───────┼─────────────────────┼───────────┼──────┤         │
│ ▾ L5x │                     │           │      │  [打开  │
│       │ ▾ L50标准款-2024配置 │           │      │   工具] │
│       │   ·                 │ 手控UI    │V118.3│         │
```

### 关键变化

| 元素 | 当前 | 新方案 |
|------|------|--------|
| 筛选区 | 纵向卡片，19 个复选框，占 40% 高度 | 单行横排标签，快速切换一种类型 |
| 资源列表 | CTk 卡片，须大量下拉 | Treeview 表格，信息密度高 3~4 倍 |
| 操作区 | 独立面板含详情卡片 | 精简为 2~3 个主按钮 + 状态文字 |
| 详情信息 | 右侧独立卡片 | Treeview 行内可见，状态栏补充 |
| 日志 | 默认可见（占位） | 默认折叠，仅底部一行 toggle |

## 三、筛选区改造：单行标签替换纵向复选框

### 设计

```
[全部] [手控UI ×] [主板程序] [蓝牙程序] [语音] ...可横向滚动
```

- 默认不选中任何类型（显示引导文字）
- 点击标签 = 单选该类型（最常用操作）
- Ctrl + 点击 = 多选
- `×` 取消单个
- `[全部]` 一键全选
- 标签超出宽度时横向滚动，不换行


## 四、资源列表改造：Treeview 表格

### 列定义

| 列 | 宽度 | 说明 |
|----|------|------|
| 型号目录名 | 220px | 完整文件系统目录名，操作员认得 |
| 固件类型 | 100px | 手控UI / 主板程序 等 |
| 版本 | 90px | V118.3.10 |
| 刷写方式 | 80px | auto_usb / tool_launch 等 |
| 文件数 | 50px | 目录内文件数量 |

树形层级：

```
系列（L5x）                    ← level 0，fg=BG_INPUT，粗体
  型号目录（L50标准款-2024）    ← level 1，正常字体
    固件类型行（手控UI）         ← level 2，叶子节点，可选中
    固件类型行（主板程序）        ← level 2
    固件类型行（蓝牙程序）        ← level 2
```

## 五、操作区精简

### 原则

操作区只做三件事：

1. **主操作按钮**（1 个，根据 flash_mode 变化）
2. **辅助动作**（打开目录、复制路径，折叠在 `▸ 更多` 里）
3. **当前选中信息**（2~3 行文字，不是独立卡片）

### 新操作区布局（宽度约 260px）

```
┌─────────────────────────┐
```

## 六、整体新布局代码结构

```
UnifiedFlashPlatform (CTk 主窗口)
└── AssetPanel (ctk.CTkFrame，充满窗口)
    ├── TopBar (单行，pack top)
    │   ├── 品牌标题
    │   ├── TypeFilterBar (横排标签筛选)
    │   └── 工具中心按钮 + 扫描目录按钮
    ├── ContentArea (pack fill=both expand=True)
    │   ├── TreePane (左，weight=4，ttk.Treeview)
    │   │   ├── ttk.Treeview（资源树，充满）
    │   │   └── 状态条（底部单行：已选中信息）
    │   └── OpsPane (右，固定宽度 260px)
    │       ├── SelectionInfo（选中资产摘要）
    │       ├── MainActionButton（主操作按钮）
    │       ├── UsbSelector（仅 auto_usb 可见）
    │       └── MoreActions（折叠区）
    └── LogBar (pack bottom，单行，点击展开)
```

## 七、实施优先级

### Phase 1 — 解决卡顿（1~2天）

1. 新建 `ui/asset_tree.py`，实现 `AssetTreeView`（`ttk.Treeview` 封装）
2. `_populate_tree()` 替代 `_render_asset_cards()`
3. 保持现有筛选逻辑不动，只改渲染层
4. 验收：筛选/搜索响应 < 100ms，滚动流畅

### Phase 2 — 修复空间问题（1天）

1. 新建 `ui/type_filter_bar.py`，实现横排标签筛选
2. `FirmwareListPanel._build_sidebar()` 中用 `TypeFilterBar` 替换 `filter_card`
3. 操作区宽度从当前 30% 改为固定 260px
4. 日志区默认折叠
5. 验收：资源列表区域占视窗高度 >70%

### Phase 3 — 精简操作区（0.5天）

1. 操作区移除 `detail_card`，选中信息改为操作区顶部 2 行文字
2. 辅助操作折叠进 `▸ 更多操作`
3. 验收：操作区无冗余信息，主按钮一眼可见

## 八、不需要改的部分

以下已有实现保持不变：

- `core/` 全部服务层：扫描、USB操作、串口、工具发现
- `asset_index.py` SQLite 索引
- `tool_center_panel.py` 工具中心窗口

- `firmware_catalog.toml` 配置
- `build_scan_result` / `build_cached_scan_result` 扫描服务

UI 层只改渲染部分，**不改数据流**。
