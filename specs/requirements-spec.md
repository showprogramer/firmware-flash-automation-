## 1. 产品定义

### 1.1 产品名称

**按摩椅程序资产管理系统**（Massage Chair Firmware Asset Manager）

### 1.2 产品定位

从单一"手控刷机工具"演进为 **固件资源管理 + 烧录执行平台**。

| 维度 | 旧定位（v0.x） | 新定位（v1.0+） |
|------|---------------|----------------|
| 服务对象 | 手控 UI 刷机 | 全部板卡固件的管理与烧录 |
| 核心能力 | 扫描 ROM/PKG → 复制到 U 盘 | 按固件类型识别 → 浏览 → 执行对应烧录动作 |
| 固件类型 | 1 类（手控） | 19 类（5 大类） |
| 台账功能 | 内置 Excel 审核表单 | **已确认移除**（永久下线，不再保留） |

### 1.3 核心价值主张

1. **统一管理**：在一个工具内浏览、检索全部 19 种板卡固件
2. **按类型分派**：根据固件类型自动匹配正确的烧录方式（USB 自动 / 串口 AT / 外部工具 / 操作说明）
3. **配置驱动**：新增固件类型优先改 TOML 配置，不优先改代码
4. **降低人工成本**：不再需要手动逐层目录找文件、记忆每种固件的工具路径

## 2. 领域术语表

| 术语 | 英文 | 定义 |
|------|------|------|
| **固件类型** | Firmware Type | 按摩椅中一块特定板卡所需烧录的程序类别，如"手控UI""主板程序""蓝牙程序"等，共 19 种 |
| **板卡** | Board / PCB | 按摩椅中的一块电路板，每块板卡需要烧录对应固件 |
| **烧录 / 刷机** | Flash / Burn | 将固件程序写入板卡的过程 |
| **刷写方式** | Flash Mode | 执行烧录的技术手段，分为 `auto_usb` / `auto_serial` / `tool_launch` / `manual_doc` / `disabled` 五种 |
| **型号** | Model | 按摩椅产品型号，如 L50、L36、L39 等 |
| **版本** | Version | 固件的版本号，如 V118.3.10 |
| **固件资源** | Firmware Asset | 一个可被系统识别的固件目录条目，包含型号、版本、固件类型、文件列表、刷写方式等属性 |
| **手控器** | Hand Controller | 按摩椅的手持控制/触摸屏设备 |
| **机芯** | Massage Mechanism | 按摩椅的机械按摩单元，分为 3D 机芯（上层）和 2D 机芯（下层） |
| **商用机** | Commercial Unit | 带投币/刷卡/支付功能的商用按摩椅 |
| **ROM 文件** | ROM File | 手控固件的主程序文件（`.rom`） |
| **PKG 文件** | PKG File | 手控固件的资源包文件（`.pkg`） |

### 3.3 刷写方式分类

| flash_mode | 含义 | 适用固件 | 系统行为 |
|-----------|------|---------|---------|
| `auto_usb` | USB 自动流程 | 手控UI、音乐蓝牙 | 清理 U 盘 → 复制文件 → 弹出（全自动） |
| `auto_serial` | 串口 AT 命令流程 | 暂无（预留） | 连接串口 → 发送 AT 命令序列 → 断开 |
| `tool_launch` | 启动外部工具 | 主板、语音、快捷键等 | 一键打开对应烧录工具，用户手动操作 |
| `manual_doc` | 显示操作说明 | 暂无（预留） | 弹出文档窗口，显示图文操作步骤 |
| `disabled` | 暂不支持 | 老化程序等 | 灰显操作按钮，不开放烧录入口 |

## 4. 功能需求

### 4.1 固件资源扫描与识别

#### FR-1.1 通用扫描引擎

- **目标**：替代当前仅识别手控目录的 `file_scan.py`，改为按 `firmware_catalog.toml` 配置驱动的通用扫描
- **输入**：用户选择的根目录路径
- **识别逻辑**：
  1. 遍历根目录下所有子目录
  2. 对每个子目录，用所有启用的固件类型配置逐一匹配
  3. 匹配规则：目录名包含 `dir_keywords` 中的任意关键词 **且** 目录下存在 `file_extensions` 中任意后缀的文件
  4. 匹配成功后，标记该目录的 `firmware_type`，提取型号和版本
- **性能要求**：扫描 1000+ 目录 < 5 秒
- **输出**：`list[FirmwareAsset]` 统一资源列表

#### FR-1.2 型号/版本提取

- **规则可配置**：型号和版本的提取规则应在 `firmware_catalog.toml` 中可配置（正则模式、路径解析模式等）
- **兜底策略**：无法从文件名提取时，尝试从路径父目录名称推断

#### FR-1.3 当前状态

- `firmware_catalog.toml` 已存在，包含 5 种固件类型（手控UI / 音乐蓝牙 / 主板程序 / 语音程序 / 快捷键程序）
- `firmware_catalog.py` 已存在，可加载和解析 TOML 配置
- **但两者均未被运行时代码使用**——当前 `handcontrol_panel.py` 仍使用旧的 `scan_service.build_scan_result()`，仅扫描手控目录
- 需要将 `firmware_catalog.py` 接入扫描流程

### 4.2 固件资源浏览与检索

#### FR-2.1 统一固件列表

- **替代当前**：手控专用列表（`handcontrol_panel.py` 中的侧边栏卡片列表）
- **列表条目字段**：型号、版本、固件类型标签、目录名、刷写方式、状态标记
- **当前状态**：已部分实现——列表卡片展示型号/版本/目录名，但缺少"固件类型"字段

#### FR-2.2 多维度筛选与排序

- **搜索**：支持按型号、版本、路径关键词搜索（已实现）
- **筛选**：按固件类型筛选、按刷写方式筛选、按状态筛选（待实现）
- **排序**：按名称/型号/版本/状态排序（已实现基本排序）

#### FR-2.3 型号聚合视图

- **目标**：提供一个"按型号"聚合的视图，展示某个型号下的全部固件集合
- **价值**：对应实际出货前 5~13 个板卡成组管理需求
- **功能**：
  - 查看该型号是否缺少某类固件
  - 展示兼容型号信息

### 4.3 烧录动作执行

## 5. 非功能需求

### 5.1 性能

| 指标 | 要求 |
|------|------|
| 扫描 1000+ 目录 | < 5 秒 |
| UI 响应 | 所有耗时操作走后台线程，界面无冻结 |
| 启动时间 | < 3 秒 |

### 5.2 可靠性

- U 盘操作失败时给出明确的中文错误提示（已实现）
- 后台任务异常通过 `messagebox` + 日志双通道通知（已实现）
- Excel 被占用时写备用文件，不丢数据（已实现）

### 5.3 安全性

- **FR-SEC-1**：`format_usb` 当前使用 `shell=True`，存在命令注入风险，**必须**改为参数列表形式（已知技术债，见 `requirements-backlog.md`）
- `eject_usb` 的 PowerShell 脚本依赖 WMI，需增加备用弹出方案

### 5.4 兼容性

| 维度 | 要求 |
|------|------|
| 操作系统 | Windows 10 / Windows 11 |
| Python | >= 3.10（实际最低；pyproject.toml 声明 >= 3.8 但推荐 3.11+） |
| 依赖 | customtkinter >= 5.2.2, openpyxl >= 3.1.0, psutil >= 5.9.0 |

### 5.5 可扩展性

- **配置驱动优先**：新增固件类型 → 修改 `firmware_catalog.toml`，代码零改动
- **刷写方式可插拔**：新增 flash_mode 只需在服务层注册新处理器
- **服务层与 UI 层分离**：当前 `core/services/` 已独立于 UI，保持此架构

### 6.4 按固件类型动态操作

操作区按钮根据当前选中条目的 `flash_mode` 动态变化。

手动分步操作默认**折叠隐藏**，仅在用户主动展开时显示（如 U 盘故障排查、单步重试等场景）：

| flash_mode | 主按钮 | 折叠区（展开后可见） |
|-----------|--------|---------------------|
| `auto_usb` | "一键智能刷机" | 清理 / 格式化 / 复制 / 弹出 |
| `auto_serial` | "自动烧录" | 连接 / 断开 / 发送命令序列 |
| `tool_launch` | "打开工具" | — |
| `manual_doc` | "查看说明" | — |
| `disabled` | 按钮灰显 | — |

### 6.5 视觉风格

- CTk 现代扁平风格（已完成迁移）
- 支持系统主题跟随（亮色/暗色）
- 窗口默认 1400x850，最小 1200x750

## 7. 技术约束

| 约束 | 说明 |
|------|------|
| 技术栈 | Python + customtkinter 桌面应用 |

| 测试 | pytest + coverage >= 80%（core 模块） |
