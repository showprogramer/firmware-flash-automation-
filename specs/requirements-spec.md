## 1. 产品定义

### 1.1 产品名称

**按摩椅程序资产管理系统**（Massage Chair Firmware Asset Manager）

### 1.2 产品定位

从单一"手控刷机工具"演进为 **固件资源管理 + 烧录执行平台**。

| 维度 | 旧定位（v0.x） | 新定位（v1.0+） |
|------|---------------|----------------|
| 服务对象 | 手控 UI 刷机 | 全部板卡固件的管理与烧录 |
| 核心能力 | 扫描 ROM/PKG → 复制到 U 盘 | 按固件类型识别 → 浏览 → 执行对应烧录动作 |
| 固件类型 | 1 类（手控） | 10+ 类（全部板卡固件） |
| 台账功能 | 内置 Excel 审核表单 | **已确认移除**（永久下线，不再保留） |

### 1.3 核心价值主张

1. **统一管理**：在一个工具内浏览、检索全部板卡固件
2. **按类型分派**：根据固件类型自动匹配正确的烧录方式（USB 自动 / 串口 AT / 外部工具 / 操作说明）
3. **配置驱动**：新增固件类型优先改 TOML 配置，不优先改代码
4. **降低人工成本**：不再需要手动逐层目录找文件、记忆每种固件的工具路径

## 2. 领域术语表

| 术语 | 英文 | 定义 |
|------|------|------|
| **固件类型** | Firmware Type | 按摩椅中一块特定板卡所需烧录的程序类别，如"手控UI""主板程序""蓝牙程序"等 |
| **板卡** | Board / PCB | 按摩椅中的一块电路板，每块板卡需要烧录对应固件 |
| **烧录 / 刷机** | Flash / Burn | 将固件程序写入板卡的过程 |
| **刷写方式** | Flash Mode | 执行烧录的技术手段，分为 `auto_usb` / `auto_serial` / `tool_launch` / `manual_doc` / `disabled` 五种 |
| **型号** | Model | 按摩椅产品型号，如 L50、L36、L39 等 |
| **版本** | Version | 固件的版本号，如 V118.3.10 |
| **固件资源** | Firmware Asset | 一个可被系统识别的固件目录条目，包含型号、版本、固件类型、文件列表、刷写方式等属性 |
| **手控器** | Hand Controller | 按摩椅的手持控制/触摸屏设备 |
| **机芯** | Massage Mechanism | 按摩椅的机械按摩单元，分为 3D 机芯（上层）和 2D 机芯（下层） |
| **商用机** | Commercial Unit | 带投币/刷卡/支付功能的商用按摩椅 |
| **系列** | Series | 产品线的逻辑分组（如 L36 系列、L39 系列），由型号目录名前缀自动推断，非文件系统物理目录 |
| **型号配置目录** | Model Config Directory | 文件系统一级目录，命名格式为 `{系列前缀}{子型号} {配置描述}`，如 `L36 3D单机芯量产家用基础款`。一台具体按摩椅的完整程序集合 |
| **固件类型目录** | Firmware Type Directory | 型号配置目录下的二级目录，如 `手控`/`主板`/`蓝牙`。命名无统一规范，需靠多关键词模糊匹配识别 |
| **ROM 文件** | ROM File | 手控固件的主程序文件（`.rom`） |
| **PKG 文件** | PKG File | 手控固件的资源包文件（`.pkg`） |
| **资产索引** | Asset Index | 程序维护的本地 SQLite 数据库，缓存扫描得到的固件资产、隐藏状态和扫描元数据，用于启动秒开、快速搜索和后台刷新 |

## 3. 固件类型与型号体系

### 3.1 文件系统实际结构

> 来源：对 `D:\按摩椅相关文件汇总\YJ-按摩椅家用，商用程序汇总` 的深度分析。57 个一级目录全部平铺在根目录下，**无系列文件夹**。系列是逻辑分组，从目录名前缀自动推断。

实际的三级物理结构：

```
根目录/
├── {型号配置目录}/          ← 一级：57 个平铺，命名 = 系列前缀 + 配置描述
│   ├── {固件类型目录}/      ← 二级：每个型号下 2~10 个子目录，命名不规范
│   │   ├── {版本目录}/      ← 三级：具体可刷版本，含实际固件文件
│   │   └── ...
│   ├── 接线图/              ← 非固件，需过滤
│   ├── 旧/                  ← 归档目录，需过滤
│   └── 照片/                ← 非固件，需过滤
```

### 3.3 固件类型识别

固件类型通过二级目录名的**多关键词模糊匹配**识别。以下是实际出现的命名变体：

| 固件类型 | key | 匹配关键词（实际出现过的目录名） |
|---------|-----|------------------------------|
| 手控UI | `handcontrol_ui` | `手控` `手控器` `手控UI` `{型号}手控` `断码屏` `断码屏亚克力手控` |
| 主板程序 | `mainboard` | `主板` `主板程序` `{型号}主板` `{客户}商用程序` |
| 蓝牙程序 | `bluetooth` | `蓝牙` `蓝牙板` `蓝牙版` `蓝牙程序` `蓝牙—语音` `三合一蓝牙版` `{型号}蓝牙` |
| 语音程序 | `voice` | `语音` `语音版` `语音程序` `语言板` `语音版三合一` `{唤醒词}语音` |
| 快捷键程序 | `shortcut_key` | `快捷键` `快捷按键` `快捷键程序` `快捷键-旋钮` `{型号}快捷键` |
| 机芯板程序 | `movement` | `机芯板` `机芯板程序` `2D机芯` `3D机芯` `机芯板上程序` `机芯板下程序` |
| 旋钮开关程序 | `knob_switch` | `旋钮` `旋钮开关` `旋钮开关程序` |
| 腿部程序 | `leg_unit` | `腿部` `美腿机` `下美腿机` `腿部新程序` |
| 三合一模块 | `triple_module` | `三合一` `三合1` `3合一` |
| 商用支付类 | `commercial_payment` | `刷卡机` `投币机` `纸币机` `白卡` `乐摇摇` `云管家` |

> **关键认知**：
> 1. 固件类型目录名极度不统一，必须靠多组关键词匹配，不能做精确名匹配
> 2. 部分子目录带有型号前缀（如 `L36手控`），部分不带（如 `手控`）
> 3. 需过滤的非固件目录：`接线图`、`旧`、`新建文件夹`、`照片`、`desktop.ini`
> 4. 跨型号引用很普遍——一个型号目录下可能出现另一个型号的固件（如 L28 目录下含 `L39MXS三合1蓝牙`）

### 3.4 每台机器烧录板卡数量

| 机型配置 | 需烧录板卡 | 数量 |
|---------|-----------|------|
| 基础家用款（单 2D 机芯） | 主板 + 手控 + 蓝牙 + 语音 + 快捷键 | **5 个** |
| 家用双机芯款（3D+2D） | 上述 5 个 + 3D 机芯板 + 2D 机芯板 | **7 个** |
| 商用款 | 家用基础上 + 商用主板 + 占座 + 刷卡 | **可多达 10 个** |
| 带腿机/膝盖机/外设 | 上述 + 1~3 个 | **可多达 13 个** |

> **关键认知**：不是"一个型号一个固件"，而是 **一个型号对应一组固件集合**。部分固件跨型号通用（如蓝牙板在 L36/L39/L50 系列间共用）。

### 3.5 刷写方式分类

| flash_mode | 含义 | 适用固件 | 系统行为 |
|-----------|------|---------|---------|
| `auto_usb` | USB 自动流程 | 手控UI、蓝牙 | 清理 U 盘 → 复制文件 → 弹出（全自动） |
| `auto_serial` | 串口 AT 命令流程 | 暂无（预留） | 连接串口 → 发送 AT 命令序列 → 断开 |
| `tool_launch` | 启动外部工具 | 主板、语音、快捷键等 | 一键打开对应烧录工具，用户手动操作 |
| `manual_doc` | 显示操作说明 | 暂无（预留） | 弹出文档窗口，显示图文操作步骤 |
| `disabled` | 暂不支持 | 老化程序等 | 灰显操作按钮，不开放烧录入口 |

## 4. 功能需求

### 4.1 固件资源扫描与识别

#### FR-1.1 通用扫描引擎

- **目标**：替代当前仅识别手控目录的 `file_scan.py`，改为按 `firmware_catalog.toml` 配置驱动的三级扫描
- **输入**：用户选择的根目录路径（如 `D:\...\YJ-按摩椅家用，商用程序汇总`）
- **识别逻辑**（匹配实际文件系统结构）：
  1. **一级扫描**：遍历根目录，识别所有型号配置目录（排除 `desktop.ini` 等非目录项）
  2. **系列推断**：根据目录名的 `[A-Z]+[0-9]+` 前缀自动推断系列归属（如 `L36*` → L36 系列）
  3. **二级扫描**：进入每个型号目录，用所有固件类型的 `dir_keywords` 多组关键词逐一匹配子目录名
  4. **匹配规则**：子目录名包含某固件类型的任意一组关键词 **且** 目录下存在 `file_extensions` 中任意后缀的文件
  5. **三级扫描**：进入固件类型子目录，识别版本/变体目录（或直接的固件文件）
  6. **过滤规则**：排除 `接线图`、`旧`、`新建文件夹`、`照片`、`desktop.ini` 等非固件目录
- **性能要求**：扫描 57 个型号目录（约 300+ 子目录）< 3 秒
- **输出**：`list[FirmwareAsset]` 统一资源列表，每个资产携带：系列、型号、固件类型、版本/变体、路径、文件列表、flash_mode

#### FR-1.2 型号/版本提取

- **型号提取**：从一级目录名截取型号前缀部分（如 `L36  3D单机芯量产家用基础款` → 型号 `L36`，完整标识保留原目录名）
- **版本提取**：从三级目录名或固件文件名中提取版本号（规则在 catalog 中可配置）
- **兜底策略**：无法从文件名提取时，尝试从路径父目录名称推断

#### FR-1.3 当前状态

- `firmware_catalog.toml` 已存在，包含 5 种固件类型（手控UI / 音乐蓝牙 / 主板程序 / 语音程序 / 快捷键程序）
- `firmware_catalog.py` 已存在，可加载和解析 TOML 配置
- **但两者均未被运行时代码使用**——当前仅扫描手控目录
- 需要：扩展 catalog 配置的多关键词匹配列表 + 接入扫描流程

#### FR-1.4 SQLite 本地资产索引

- **目标**：把项目定位从“每次现场扫盘的目录浏览器”升级为“本地固件资产索引器 + 工具启动器”，保障打包为公司内部 exe 后启动和检索体验稳定。
- **存储位置**：默认在 exe / 应用根目录旁生成 `fwasset.db`，与 `config.toml`、`firmware_catalog.toml` 同级，便于内部部署和备份。
- **索引内容**：
  - `assets`：保存 `FirmwareAsset` 扫描结果，至少包含 `series` / `model` / `model_directory_name` / `model_directory_path` / `firmware_type` / `firmware_label` / `flash_mode` / `version` / `path` / `directory_name` / `files_json` / `modified_time` / `scanned_at`
  - `hidden_items`：保存被隐藏的型号目录或固件类型，按目录绝对路径持久化
  - `scan_meta`：保存根目录、最后扫描时间、schema 版本等元信息
- **启动行为**：
  1. 应用启动先读取 SQLite 中最近一次索引结果并渲染 UI，避免启动时全量扫盘卡顿。
  2. 若没有索引，显示空状态和“首次扫描”提示。
  3. 用户点击扫描后，后台线程刷新真实目录并写回 SQLite。
- **搜索/筛选行为**：搜索、固件类型筛选、树形导航展开收起默认基于内存索引或 SQLite 查询，不应在每次交互时重新遍历文件系统。
- **刷新策略**：
  - 手动“扫描根目录”触发全量刷新。
  - 刷新时用路径和修改时间判断变更，删除不存在的资产记录，清理已不存在路径对应的隐藏记录。
- **可靠性要求**：SQLite schema 需支持版本号和轻量迁移；数据库损坏时不影响程序启动，应给出中文提示并允许重新扫描生成。

### 4.2 固件资源浏览与检索

#### FR-2.1 型号优先的树形导航

核心设计原则：**操作员的工作流是"先选型号→再看该型号下有哪些固件"**，与文件系统的物理结构一致。

- **替代当前**：`CTkSegmentedButton` 模式切换（"手控模式"/"音乐模式"）
- **树形结构**：

```
[搜索框: 输入型号名或固件类型关键词...]

▼ L36 系列 (22)
  ▼ L36 3D单机芯量产家用基础款
      ├ 手控UI          ← 固件类型作为型号下的子条目
      ├ 主板程序
      ├ 蓝牙程序
      ├ 语音程序
      ├ 快捷键程序
      └ 机芯板程序
  ▼ L36 双机芯上-3D 下-2D 程序
      ├ ...
  ▶ L36 泰币商用机
▼ L39 系列 (9)
  ...
```

- **系列**：自动推断的逻辑分组，可折叠/展开
- **型号配置目录**：显示原始目录名（保留完整配置描述），作为导航主节点
- **固件类型**：型号下的叶子节点，带 firmware_type 标签和版本数量标记
- **搜索**：输入关键词，实时过滤不匹配的树节点，匹配项高亮展开

#### FR-2.2 条目隐藏（减少视觉噪音）

- **目标**：操作员可以隐藏暂时不需要的型号目录或固件类型，减少列表噪音
- **行为**：
  - 右键菜单 → "隐藏此项"（或通过按钮操作）
  - 隐藏状态按**目录绝对路径**存储，跨会话持久化
  - 提供"显示已隐藏项目"开关，可恢复隐藏条目
  - 操作员在文件系统中删除目录后，刷新自动移除（无需隐藏）
- **不操作文件系统**：隐藏只是工具内的显示过滤，不删除/移动任何文件
- **边界情况**：如果操作员隐藏了 `L36泰币商用机` 后又把该目录改了名字，隐藏状态失效——新名字作为新条目重新出现

#### FR-2.3 详情展示

- **选中固件类型叶子节点时**，操作区展示：
  - 型号完整名称、固件类型标签、版本列表、文件清单、路径、修改时间
  - 根据 flash_mode 动态渲染操作按钮（见 FR-3）

#### FR-2.4 型号聚合视图（P2）

- **目标**：提供一个"按型号"聚合的视图，展示某个型号下的全部固件集合及缺失情况
- **价值**：对应实际出货前 5~13 个板卡成组管理需求
- **功能**：
  - 查看该型号是否缺少某类固件
  - 展示兼容型号信息

### 4.3 烧录动作执行

#### FR-3.1 按 flash_mode 分派动作

系统根据固件类型的 `flash_mode` 决定可用操作：

| flash_mode | 操作按钮 | 实现状态 |
|-----------|---------|---------|
| `auto_usb` | "一键智能刷机" + 手动分步操作（清理/格式化/复制/弹出） | **已实现**（手控和音乐面板） |
| `auto_serial` | "连接串口" → "发送 AT 命令序列" | **部分实现**（音乐面板有串口连接和 AT 收发，但缺少固定命令序列编排） |
| `tool_launch` | "打开烧录工具" | **待实现**（工具中心） |
| `manual_doc` | "查看操作说明" | **待实现** |
| `disabled` | 按钮灰显 | **待实现** |

#### FR-3.2 自动化流程扩展路线

| 优先级 | 固件类型 | 目标刷写方式 | 说明 |
|--------|---------|-------------|------|
| **P0** | 主板程序 | 待确认 | 需确认实际烧录方式（USB？串口？专用烧录器？） |

## 6. UI/UX 需求

### 6.1 当前架构（过渡态，待改造）

当前窗口为 `UnifiedFlashPlatform`（`shell.py`），采用**双模式切换**架构：

- **手控模式** → `HandcontrolPanel`：侧边栏列表 + 刷机操作卡 + 资源详情 + 运行日志
- **音乐模式** → `MusicPanel`：串口摘要 + 音乐 U 盘刷机卡 + 串口 AT 控制卡 + 日志 Tab
- 共享基类：`BaseFlashPanel`（`base_panel.py`）
- 切换控件：`CTkSegmentedButton`（"手控模式" / "音乐模式"）

**此架构存在明确缺陷，已确认需要改造：**

| 问题 | 说明 |
|------|------|
| 命名混乱 | "手控"是一种固件类型，不是一种"应用模式"。用户无法从"手控模式"这个名字理解这是什么功能 |
| 不可扩展 | 无法靠不断增加 SegmentedButton 选项来承载更多固件类型——每加一种类型就得新建一个 Panel 类 |
| 信息孤岛 | 手控和音乐的资源列表完全隔离，无法在一个视图中浏览全部固件资源 |
| 代码重复 | `HandcontrolPanel` 和 `MusicPanel` 各自实现了类似的 U 盘操作、日志区、侧边栏，难以维护 |
| 布局比例错误 | 侧边栏（小）放导航列表，主区域（大）放日志和详情——但操作员 90% 时间在看列表找程序，日志大部分人根本不看 |

**改造方向**：不再按"固件类型"切换面板，改为**型号优先的树形导航 + 大侧边栏 + 按 flash_mode 动态渲染操作区**。详见下方 6.3 目标布局。

- **日志默认折叠**：底部折叠条，点击展开，仅排查问题时使用
