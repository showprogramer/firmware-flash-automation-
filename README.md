# Firmware Flash Automation

一套**可扩展的固件刷机自动化框架**，用于简化嵌入式设备固件的批量部署、测试和文档管理。

当前实现模块：**手控 UI**。未来支持：蓝牙、语音、主板等多源固件刷机工作流。

## 项目特色

- **模块化架构**：业务逻辑与 UI 完全解耦，支持快速扩展新模块处理器
- **通用扫描与字段提取**：自适应识别固件型号、版本、文件类型
- **工作流编排**：配置化的刷机流程（清理 → 复制 → 格式化 → 写入 → 退出）
- **测试管理**：集成 Excel 台账，自动同步测试状态和操作记录
- **多维度排序**：支持按型号/版本/状态/时间等灵活排序，便于工作优先级管理
- **后台任务**：I/O 密集操作无阻塞，UI 始终可响应

## 核心功能

### 扫描与识别
- 递归扫描目标目录，自动识别包含固件文件的可处理目录
- 智能提取型号、版本号等关键字段（支持规则自定义和路径补偿识别）

### 设备准备
- USB 设备清理（删除指定扩展名和文件名）
- FAT32 格式化及安全弹出
- 设备健康检查与故障诊断

### 固件部署与测试
- 一键执行工作流：清理 → 复制 → 设备操作 → 写入 Excel
- 测试状态管理：记录每个固件的测试进度和结果
- 自动备用文件生成（当主文件被占用时）

### 数据管理
- Excel 集成：自动汇总测试台账，支持自定义工作表和字段
- 多维度排序：按型号、版本号、文件夹名、测试状态等维度灵活排序
- 操作日志：记录每次扫描、烧写、测试的完整历史

## 架构设计

采用三层解耦设计，**业务逻辑与 UI 完全分离**：

```
┌─────────────────────┐
│   UI Layer          │  app.py
│   (UI 交互)         │  - 本地状态管理（排序、搜索、过滤）
│                     │  - 事件驱动、线程池管理
└──────────┬──────────┘
           │
┌──────────▼──────────┐
│  Service Layer      │  core/services/
│  (业务编排)         │  - 工作流执行
│                     │  - Excel 操作
│                     │  - USB 外设管理
└──────────┬──────────┘
           │
┌──────────▼──────────┐
│  Core Layer         │  core/
│  (纯业务函数)       │  - 扫描、排序、字段提取
└─────────────────────┘  - 无状态、可单独测试
```

### 扩展性设计

**添加新的固件模块只需：**

1. **定义模块处理器** → `core/handlers/{module}.py`
   - 实现文件识别规则
   - 定义字段提取逻辑
   
2. **注册模块** → `core/module_registry.py`
   - 在配置中启用模块
   - 自动纳入通用工作流

3. 其他代码**零改动**

## 运行环境

- **操作系统**：Windows 10/11（依赖 PowerShell 命令调用、盘符识别）
- **Python**：`>= 3.8`（推荐 `3.11+` 使用内置 `tomllib`）
- **依赖库**：
  - `openpyxl>=3.1.0` — Excel 读写
  - `psutil>=5.9.0` — 进程/设备检测
  - `tomli>=2.0.0` — 配置文件（仅 Python 3.8-3.10）

### 方式一：使用 uv（推荐）

```powershell
uv venv .venv
.venv\Scripts\Activate.ps1
uv sync --extra dev
```

```powershell
uv run python app.py
```

### 方式二：使用 pip

```powershell
python -m venv .venv

```

## 使用步骤

1. 准备并激活虚拟环境（见“安装依赖”）。
2. 启动程序：

```powershell
python app.py
```

3. 首次运行前检查 `config.toml`：
- `paths.root_dir`：程序扫描根目录。
- `paths.excel_path`：Excel 台账路径（相对路径按项目根目录解析）。
- `excel.sheet` 与 `excel.header_row`：Excel 工作表与表头起始行。
- `usb.junk_extensions` 与 `usb.junk_filenames`：U 盘清理规则。
- `scan.*`：扫描识别规则，可配置 ROM/PKG 扩展名、目录排除词、型号正则、版本正则和路径补偿正则。
4. 在界面中点击"扫描目录"，选择目标固件记录。
5. 选择 U 盘盘符并执行刷机步骤，或直接使用"一键执行"。
6. 完成后在"审核填写"页保存测试结果，自动写入 Excel。
7. 若出现 Excel 占用提示，先关闭 WPS/Excel，再补录或合并备用文件。

### 1) 检测不到 U 盘

- 先点击“刷新”按钮重试。
- 确认 U 盘已被系统识别并有盘符。
- 部分设备分区格式不在常见可移动盘识别范围内时，建议先在系统中重新挂载。

### 2) Excel 写入失败或提示被占用

- 关闭正在打开目标文件的 WPS/Excel。
- 查看同目录下 `*_刷机记录_待导入.xlsx` 备用文件是否已生成。
- 若失败原因不是占用，请根据弹窗错误信息排查路径权限、文件损坏或工作表名配置。

### 3) 型号或版本识别不准确

- 优先检查 `config.toml` 中 `[scan]` 的识别规则是否与当前固件命名一致。
- 若文件名不完整，工具会尝试按 `path_model_patterns` 从路径推断型号。
- 默认已内置手控规则；切换其他程序命名规范时可只改配置，无需改代码。

### 4) 启动时报依赖缺失

- 确认在虚拟环境中运行。
- 使用 uv 时优先执行 `uv sync --extra dev`。
- 使用 pip 时重新安装依赖：`pip install openpyxl>=3.1.0 psutil>=5.9.0 pytest>=8.0.0 pytest-cov>=5.0.0`。

### 5) `config.toml` 修改后未生效

- 启动后查看日志顶部配置加载提示。
- 若显示“配置回退”，请按提示检查 `config.toml` 路径、语法，或在 Python 3.8-3.10 下确认已安装 `tomli`。
